**结构分析**：
- ❌ **features 返回为字符串数组**而非结构化 dict，完全不符合 JSON Schema

- ❌ 材料被错误识别为 "Aluminum"（应为 HT200 铸铁）

- ❌ `overall_shape` 返回了描述性文本 "阶梯轴套类零件..." 而非标准枚举值
- ❌ 多识别了一个不存在的 φ4 孔
- ❌ 漏识别了密封槽特征

**量化分析**：
- ❌ **全部 8 条尺寸返回为字符串**，而非结构化 `{value, tolerance, type, feature_ref}` 对象

- ⚠️ 粗糙度只提取到 2 条（缺失 Ra 3.2 和 Ra 6.3）

## 四、发现的系统性问题（优化重点）

### 🔴 问题 1：Prompt 模板版本冲突（影响最大）

| 位置 | 模板质量 | Schema 严格度 |
|------|----------|---------------|
| `config/结构分析模版.txt` | **新版** — 严格 JSON Schema，含 id/count/location/notes，英文 type 枚举 | 高 |
| `settings.json → structure_analysis` | **旧版** — 宽松 JSON Schema，无 id，中文 type 枚举，`approximate_size` | 低 |

**现状**：`llm_service.py` 优先使用 settings.json 中的模板（因为非空），而非 `config/*.txt` 的精炼版。这意味着当前系统实际使用的是旧版模板！

**影响**：旧版模板要求松散，模型（尤其是弱模型）容易输出非结构化数据。学生图的分析质量崩溃与此直接相关。

**建议**：将 config/*.txt 的精炼版模板同步到 settings.json 中。

### 🔴 问题 2：模型输出格式不稳定

mimo-v2.5 对学生图的输出严重偏离 JSON Schema：
- features 变成字符串数组
- dimensions 变成字符串数组
- 枚举值被自由文本替代

这说明需要：
1. 更强的模型（如 qwen3.6-plus）或
2. 在 prompt 中加强格式约束，或
3. 增加 structured output / JSON mode 强制

### 🟡 问题 3：_simplify_quantitative 缺乏容错

`llm_service.py:_simplify_quantitative()` 假设 dimensions 中的每项都是 dict，不处理字符串。遇到非标准输出直接崩溃。需增加防御性编程。

### 🟡 问题 4：token 用量数据丢失

`save_json()` 去掉了 `_usage`, `_model` 等下划线开头的字段，导致前 3 次调用的 token 数据无法回溯。应保留原始 API 响应字段。

### 🟡 问题 5：4 次串行 LLM 调用 = 85 秒总延迟

当前管线是严格串行的：
```
ref_analyze (24.5s) → stu_analyze (17.2s) → phase1 (23.6s) → phase2 (19.6s)
```

实际上参考图分析和学生图分析可以并行（互不依赖），可节省约 17s。

### 🟢 亮点：参考图分析质量好

对于「标准答案」式的参考图，新版 JSON Schema 能很好地引导模型输出结构化数据。模型正确提取了所有特征、尺寸、公差和粗糙度。

## 五、优化路线建议

### 短期（立即执行）

1. **同步 prompt 模板**：将 config/*.txt 的精炼版模板写入 settings.json
2. **增强容错**：`_simplify_quantitative()` 处理字符串/非标准格式
3. **保留原始字段**：不 strip `_usage` 类型的内部字段，便于调试

### 中期

4. **并行化分析**：参考图和学生图分析可并发执行（减少 ~17s）
5. **换用更强模型**：对格式遵循要求高的步骤使用 qwen3.6 等强模型
6. **添加 JSON Mode**：强制 LLM 输出合法 JSON（需 API 支持）

### 长期

7. **结构分析专用模型微调**：对工程图特征识别做 fine-tune
8. **缓存参考图分析**：同一参考图的分析结果可跨学生复用
9. **流式评分**：分析结果逐步产出，不需等全部完成

## 七、当前 Prompt 模板版本对比

### settings.json 中的旧版（正被使用）

```json
"features": [
  {
    "type": "通孔|螺纹孔|沉头孔|键槽|筋板|倒角|圆角|退刀槽|轴肩|卡簧槽|密封槽|油槽|其他",
    "description": "特征的形状、位置和数量描述",
    "approximate_size": "估计的尺寸范围"
  }
]
```

### config/*.txt 中的新版（未被使用）

```json
"features": [
  {
    "id": "F01",
    "type": "从以下选择: 通孔/盲孔/沉头孔/螺纹孔/销孔/光孔/槽/键槽/凸台/加强筋/倒角/圆角/退刀槽/越程槽/齿轮/花键/螺纹/锥面/扁位/其他",
    "count": 1,
    "location": "描述位置，如'零件左端面'或'中间段上表面'",
    "notes": "补充描述，如'贯穿件，与F03键槽相交'或'M20螺纹孔'"
  }
]
```

新版差异：
- 增加了 `id` 字段（F01, F02...），支持后续量化分析的 `feature_ref`
- 增加了 `count`（数量）和 `location`（位置）
- 特征类型枚举更完整（21 种 vs 13 种）
- 去掉了模糊的 `approximate_size`，改用结构化的 `notes`
