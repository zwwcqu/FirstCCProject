## 二、输出质量对比（关键差异）

### features 字段格式

| | 第一轮（旧模板） | 第二轮（新模板） |
|--|-----------------|-----------------|
| 格式 | `["螺纹孔 (M30X2)", "光孔 (Φ18H9, ...)", ...]` | `[{"id":"F01","type":"螺纹","count":1,"location":"零件左端外圆","notes":"M30×2外螺纹"}, ...]` |
| 类型 | **字符串数组** ❌ | **结构化 dict** ✅ |
| 数量 | 7 条（压缩后） | **9 条**（逐条完整） |

### dimensions 字段格式

| | 第一轮（旧模板） | 第二轮（新模板） |
|--|-----------------|-----------------|
| 格式 | `["总长: 80", "各段长度: 30, 45±0.2, ..."]` | `[{"id":"D01","type":"长度","value":80,"unit":"mm","tolerance":"未注公差",...}, ...]` |
| 类型 | **字符串数组** ❌ | **结构化 dict** ✅ |
| 数量 | 8 条压缩字符串 | **20 条**逐条标注 |

### 根本原因

settings.json 中存的是旧版模板（来自 settings.example.json），其 JSON Schema 要求松散：

```json
// 旧版（当前生效）
"features": [{"type": "...", "description": "...", "approximate_size": "..."}]  // 无 id, 无 count

// 新版（config/*.txt）  
"features": [{"id": "F01", "type": "...", "count": 1, "location": "...", "notes": "..."}]
```

`llm_service.py` 优先取 settings.json 中的模板（非空即用），导致 config/*.txt 的精炼模板从未生效。

### 3.1 学生图合并分析（30.4s, 9782 tokens）

**结构分析质量**：✅ 大幅改善，仍有瑕疵

## 五、问题分级

### 🔴 P0：Prompt 模板版本冲突（已确认）

**现状**：settings.json 的旧版宽松模板覆盖了 config/*.txt 的新版严格模板。

**影响**：模型输出质量严重下降——features/dimensions 退化为字符串数组，`_simplify_quantitative()` 直接崩溃。

**修复**：
```
方案 A（推荐）：将 config/*.txt 内容写入 settings.json 的 prompt_templates
方案 B：修改 llm_service.py，文件模板优先于 settings 模板
```

### 🔴 P1：`_simplify_quantitative()` 无容错

遇到非 dict 元素直接 `AttributeError`，导致整个评分管线崩溃。

### 🟡 P2：模型识别错误（mimo-v2.5 能力边界）

| 错误 | 严重性 |
|------|--------|
| 材料 Aluminum 幻觉 | 中（影响评分有限） |
| 退刀槽→键槽 误分类 | 中（影响阶段一特征对比） |
| 形状 轴类→应为箱体 | 中 |
| 漏识别密封槽 | 中 |
| 粗糙度只提取 2/4 条 | 高（影响阶段二粗糙度评分） |
| thread_specs 为空 | 中 |

### 🟡 P3：参考图分析不能复用

参考图分析需要跨学生复用，但目前系统没有缓存机制（201 的缓存是手动存的）。

### 🟢 P4：3 次 LLM 调用 82 秒

学生分析 + 阶段一可并行（互不依赖），理论可省 30s。

## 六、优化建议

### 立即执行
1. **同步模板**：将 config/*.txt 写入 settings.json prompt_templates
2. **容错补丁**：`_simplify_quantitative()` 过滤非 dict 元素

### 短期
3. **并行化**：学生分析 ∥ 阶段一（节省 ~20s）
4. **模板选择逻辑修正**：文件模板优先于 settings（或将 settings 作为 override 而非 default）

### 中期
5. **模型升级**：mimo-v2.5 对学生图（不规范的工程图）识别能力不足，建议 qwen3.6-plus 或更强 vision model
6. **JSON Mode**：强制 LLM 输出合法 JSON（需 API 支持 structured output）
